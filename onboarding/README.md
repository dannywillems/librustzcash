# librustzcash onboarding documentation site

This directory holds a [Docusaurus](https://docusaurus.io/)-powered
graduate-level course on `librustzcash`. The published site is built
and deployed automatically by the GitHub Actions workflow
`.github/workflows/onboarding-docs.yml` on every push to the
`onboarding` branch.

The content lives in `docs/`. Start with `docs/index.md`.

## Local development

```sh
make doc-install   # install dependencies (one time)
make doc-dev       # start dev server (live reload at http://localhost:3000)
make doc-build     # production build into ./build
make doc-serve     # serve the built site locally
make doc-clear     # clear Docusaurus cache
```

The Makefile is the canonical interface; do not use npm scripts
directly.

## Importing code from the workspace

We use [`docusaurus-theme-github-codeblock`](https://github.com/christian-bromann/docusaurus-theme-github-codeblock)
(same approach as the
[o1-labs/mina-rust](https://github.com/o1-labs/mina-rust/blob/develop/website/docs/developers/referencing-code-in-documentation.md)
documentation site) to embed actual source code from the workspace
into the chapters at build time. Inside a `.md` chapter:

````markdown
<!-- CODE_REFERENCE: components/zcash_protocol/src/consensus.rs#L18-L20 -->

```rust reference title="components/zcash_protocol/src/consensus.rs"
https://github.com/zcash/librustzcash/blob/main/components/zcash_protocol/src/consensus.rs#L18-L20
```
````

- The `reference` info-string keyword tells the plugin to fetch the
  snippet from GitHub at build time.
- The `<!-- CODE_REFERENCE: -->` HTML comment is the source-of-truth
  marker (same convention as mina-rust); a CI script can verify all
  references point to existing code.
- Plain Markdown is sufficient; **no MDX** required for these.

Convert a chapter to `.mdx` only when you need to embed the *whole*
contents of a file (with React-style raw-loader imports), not just a
line range.

## Deployment

The GitHub Pages source for this fork is set to "Deploy from a
branch" with branch `onboarding` and folder `/ (root)`. The
workflow therefore:

1. Builds the Docusaurus site under `onboarding/`.
2. Publishes the built static output (`onboarding/build/`) to the
   **root** of the `onboarding` branch via `peaceiris/actions-gh-pages`
   with `keep_files: true`, so the existing source under `onboarding/`
   is preserved.
3. Tags the deploy commit with `[skip ci]` so it does not re-trigger
   the workflow.

After the first successful run, the site lives at
`https://dannywillems.github.io/librustzcash/`.

If you fork this repo under a different account, update the `url`,
`baseUrl`, `organizationName`, and `projectName` fields in
`docusaurus.config.ts`.

## Layout

```
onboarding/
  docs/                  Chapter sources (Markdown + KaTeX + code refs)
    index.md             Site homepage (slug: /)
    01-..-..md           Each chapter; numeric prefix orders the sidebar
  src/css/custom.css     Theme overrides
  static/                Static assets served at site root
  docusaurus.config.ts   Site configuration
  sidebars.ts            Autogenerated sidebar
  package.json           Node dependencies (no scripts; use Makefile)
  package-lock.json      Pinned dependency tree
  tsconfig.json
  Makefile               make doc-* targets
```

## Conventions

- Chapter filenames use numeric prefixes (`01-`, `02-`, ...) which
  Docusaurus parses into sidebar order automatically.
- Cross-references between chapters use relative paths
  (`./01-overview-and-roadmap.md`); Docusaurus resolves them at
  build time.
- Math is wrapped in `$...$` (inline) or `$$...$$` (display); the
  remark-math + rehype-katex plugins render it.
- `.md` files are parsed as plain CommonMark (not MDX). This keeps
  LaTeX-heavy content safe from MDX parser strictness.
- Source code is **embedded by reference** (see above). Prefer
  reference blocks over copy-pasted snippets so the docs cannot
  drift from the canonical source.
