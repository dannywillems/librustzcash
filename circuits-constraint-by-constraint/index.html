24 - Circuits, constraint by constraint

1. Why this chapter exists​

The Sapling Spend circuit, the Sapling Output circuit, and the Orchard Action circuit are the cryptographic heart of Zcash's shielded protocols. Earlier chapters described them at the statement level. A contributor who modifies a circuit, adds a public input, or changes a generator without understanding each constraint will either break soundness or invalidate the trusted setup. This chapter walks every clause in the order the prover witnesses and the verifier checks, with an explicit "attack on omission" note showing what fails if the clause is removed. The implementations live in the external sapling-crypto and orchard crates, consumed by this workspace via zcash_proofs/src/circuit (for Sprout) and the high-level builders in zcash_primitives/src/transaction/builder.rs.

Constraint counts are approximate; exact numbers depend on gadget implementation and shift over time as optimisations land.

Definition 2.4 (Incomplete addition). Let EEE be an elliptic curve in short Weierstrass form y2=x3+ax+by^2 = x^3 + a x + by2=x3+ax+b. 3.3 Clause: nk=[nsk] Gnk\mathsf{nk} = [\mathsf{nsk}]\,G^{\mathsf{nk}}nk=[nsk]Gnk​

Scalar mul of a fixed generator by a 252-bit secret. Using the fixed-base windowed comb gadget in sapling-crypto:

  • 252 bits of nsk\mathsf{nsk}nsk are decomposed.
  • For each 3-bit window, a constant-time table select picks one of 8 precomputed multiples.
  • The selected multiples are summed.

Constraint cost: ~750.

Attack on omission: a witnessed nk\mathsf{nk}nk unrelated to nsk\mathsf{nsk}nsk lets the spender choose nk\mathsf{nk}nk post-hoc, allowing nullifier prediction for unspent notes or forged nullifier collisions.

3.4 Clause: ivk=CRHivk(ak,nk)\mathsf{ivk} = \mathsf{CRH}^{\mathsf{ivk}}(\mathsf{ak}, \mathsf{nk})ivk=CRHivk(ak,nk)​

CRHivk\mathsf{CRH}^{\mathsf{ivk}}CRHivk is BLAKE2s-256 of the concatenated encodings of ak\mathsf{ak}ak and nk\mathsf{nk}nk (as uuu-coordinates) plus parity bits. Implementing BLAKE2s in R1CS is expensive: one of the largest sub-circuits in Sapling, ~16,000 constraints.

The output is reduced modulo ℓJ\ell_JℓJ​ to produce ivk\mathsf{ivk}ivk. The reduction is a controlled bit-truncation rather than a full modular reduction, valid because ℓJ<2252\ell_J < 2^{252}ℓJ​<2252 and the top bits are zeroed.

Attack on omission: an unmoored ivk\mathsf{ivk}ivk would let the prover claim ownership of arbitrary pkd\mathsf{pk}_dpkd​ they do not control.

3.8 Clause: Merkle path​

For each layer ℓ∈{0,1,…,31}\ell \in \{0, 1, \ldots, 31\}ℓ∈{0,1,…,31}:

  1. Witness the auth-path sibling at this layer and a boolean indicating "is the current node the left or right child".

3.9 Clause: dummy spend handling​

If v=0v = 0v=0, the Merkle path check is skipped: a dummy spend does not correspond to a real note in the tree. The circuit implements this by computing the Merkle output and a "dummy override" output, then conditionally selecting between them based on v=0v = 0v=0. The override does not set the anchor to a free choice; the dummy clause makes the Merkle-path computation a no-op while all other clauses still hold. The effect: when v=0v = 0v=0, the cm\mathsf{cm}cm may be any well-formed commitment but no anchor membership is claimed.

Implemented as an if-then-else over boolean multiplexing in bellman gadgets.

Attack on omission: without the dummy mechanism, every spend revealed the bundle's true input count, leaking metadata.

Clause: subgroup check on gdg_dgd​​

The circuit asserts that the witnessed gdg_dgd​ is in the prime- order subgroup. For Jubjub this requires checking [ℓJ] gd=O[\ell_J]\,g_d = \mathcal{O}[ℓJ​]gd​=O, which is expensive but unavoidable.

Why no anchor or nullifier​

An Output creates value; it does not prove the new note is in the tree (it adds itself) and does not have a nullifier (it has not been spent).

3.16 Orchard Action statement​

The Action circuit unifies Spend and Output. From chapter 05: for each Action, the prover knows:

  • Old note: (vold,gdold,pkdold,ρold,ψold,rcmold,auth-path,ak,nk,rivk,α)(v_{\text{old}}, g_d^{\text{old}}, \mathsf{pk}_d^{\text{old}}, \rho^{\text{old}}, \psi^{\text{old}}, \mathsf{rcm}^{\text{old}}, \text{auth-path}, \mathsf{ak}, \mathsf{nk}, \mathsf{rivk}, \alpha)(vold​,gdold​,pkdold​,ρold,ψold,rcmold,auth-path,ak,nk,rivk,α).
  • New note: (vnew,gdnew,pkdnew,ψnew,rcmnew)(v_{\text{new}}, g_d^{\text{new}}, \mathsf{pk}_d^{\text{new}}, \psi^{\text{new}}, \mathsf{rcm}^{\text{new}})(vnew​,gdnew​,pkdnew​,ψnew,rcmnew).

Such that:

  1. If spends enabled: the old commitment is in the tree at the public anchor.
  2. ρnew=nfold\rho^{\text{new}} = \mathsf{nf}^{\text{old}}ρnew=nfold - the new note's ρ\rhoρ chains from the spent nullifier.
  3. Nullifier formula yields public nf\mathsf{nf}nf.
  4. rk=ak+[α] Gak\mathsf{rk} = \mathsf{ak} + [\alpha]\,G^{\mathsf{ak}}rk=ak+[α]Gak (public).
  5. cmnew=NoteCommitrcmnew(…)\mathsf{cm}^{\text{new}} = \mathsf{NoteCommit}^{\mathsf{rcm}^{\text{new}}}(\ldots)cmnew=NoteCommitrcmnew(…) matches public cmx\mathsf{cmx}cmx.
  6. cvnet=[vold−vnew] V+[rcv] R\mathsf{cv}^{\text{net}} = [v_{\text{old}} - v_{\text{new}}]\,V + [\mathsf{rcv}]\,Rcvnet=[vold​−vnew​]V+[rcv]R (public).
  7. If outputs enabled: epk=[esk] gdnew\mathsf{epk} = [\mathsf{esk}]\,g_d^{\text{new}}epk=[esk]gdnew​.
  8. vold,vnew∈[0,264)v_{\text{old}}, v_{\text{new}} \in [0, 2^{64})vold​,vnew​∈[0,264).
  9. ivk=Extract(SinsemillaCommitrivk(ak,nk))\mathsf{ivk} = \mathsf{Extract}( \mathsf{SinsemillaCommit}^{\mathsf{rivk}}( \mathsf{ak}, \mathsf{nk}))ivk=Extract(SinsemillaCommitrivk(ak,nk)) and pkdold=[ivk] gdold\mathsf{pk}_d^{\text{old}} = [\mathsf{ivk}]\,g_d^{\text{old}}pkdold​=[ivk]gdold​.

Public inputs per Action: anchor\mathsf{anchor}anchor, cvnet\mathsf{cv}^{\text{net}}cvnet, nf\mathsf{nf}nf, rk\mathsf{rk}rk, cmx\mathsf{cmx}cmx, epk\mathsf{epk}epk, plus the two flag bits.

3.17 Halo 2 column layout​

The Orchard circuit uses ~10 advice columns over a 2112^{11}211-row domain. Each row is a small piece of computation; together the rows realise the full statement.

Custom gate groups (approximate):

  • q_ecc_add, q_ecc_double: Pallas point arithmetic.
  • q_sinsemilla: Sinsemilla chain steps.
  • q_poseidon: Poseidon hash steps.
  • q_lookup_range: range checks via lookup.
  • q_lookup_sinsemilla_S: Sinsemilla 10-bit chunk to point.
  • q_decomposition: bit-decomposition gates.
  • q_constraints: high-level equality gates.

Each gate is a polynomial identity over advice columns, gated by a selector.

3.18 Sinsemilla in-circuit​

For the Note Commitment, the prover uses Sinsemilla:

  1. Bit-decompose the input (vvv, gdg_dgd​, pkd\mathsf{pk}_dpkd​, ρ\rhoρ, ψ\psiψ) into 10-bit chunks.
  2. Each chunk is looked up in the Sinsemilla generator table: (chunk,S(chunk))(\text{chunk}, S(\text{chunk}))(chunk,S(chunk)).
  3. Iteratively combine via the incomplete-addition gate.
  4. After all chunks are processed, add the rcm\mathsf{rcm}rcm blinding.

The Sinsemilla path costs ~300 rows for typical inputs.

Pitfall: incomplete addition fails when its operands coincide (chapter 13). The circuit must prove the operands are distinct, typically by witnessing intermediate accumulator values and asserting non-equality in a gate.

3.19 Merkle path with Sinsemilla​

Each of the 32 Merkle layers uses one Sinsemilla hash of (layer index, left, right). The layer index is part of the personalisation DMH,ℓD_{\text{MH}, \ell}DMH,ℓ​ encoded as a Sinsemilla domain.

Cost per layer: ~150 rows. Times 32: ~4,800 rows.

3.20 The ρnew=nfold\rho^{\text{new}} = \mathsf{nf}^{\text{old}}ρnew=nfold trick​

The novel Orchard idea: after computing nfold\mathsf{nf}^{\text{old}}nfold, the circuit feeds it as ρnew\rho^{\text{new}}ρnew into the new note commitment. This eliminates the need for an extra Pedersen-hash- based position-mix as in Sapling. The new note's ρ\rhoρ is fully determined by the Action's inputs; the prover cannot choose it freely.

Implementation: an explicit copy constraint from "the row that outputs nfold\mathsf{nf}^{\text{old}}nfold" to "the row that takes ρnew\rho^{\text{new}}ρnew as input".

3.21 Nullifier derivation​

The Orchard nullifier:

nf  =  Extract([Hash(nk,ρold)+ψold] Knf  +  cmold),\mathsf{nf} \;=\; \mathsf{Extract}\bigl( [\mathsf{Hash}(\mathsf{nk}, \rho^{\text{old}}) + \psi^{\text{old}}]\,K_{\text{nf}} \;+\; \mathsf{cm}^{\text{old}}\bigr),nf=Extract([Hash(nk,ρold)+ψold]Knf​+cmold),

with Hash\mathsf{Hash}Hash a Poseidon-based PRF keyed by nk\mathsf{nk}nk.

Sub-circuit: ~200 rows for Poseidon, ~100 for the scalar mul, ~50 for the addition and extract.

3.22 Value commitment (net)​

Net value: vnet=vold−vnewv^{\text{net}} = v_{\text{old}} - v_{\text{new}}vnet=vold​−vnew​, range-checked to lie in [−(264−1),264−1][-(2^{64} - 1), 2^{64} - 1][−(264−1),264−1]. Then

cvnet=[vnet] VOrch+[rcv] ROrch.\mathsf{cv}^{\text{net}} = [v^{\text{net}}]\,V_{\text{Orch}} + [\mathsf{rcv}]\,R_{\text{Orch}}.cvnet=[vnet]VOrch​+[rcv]ROrch​.

In-circuit cost: ~150 rows.

3.23 CommitIvk in-circuit​

The Orchard incoming viewing key is derived inside the circuit:

ivk  =  Extract(SinsemillaCommitrivk(ak,nk)).\mathsf{ivk} \;=\; \mathsf{Extract}(\mathsf{SinsemillaCommit}^{\mathsf{rivk}}( \mathsf{ak}, \mathsf{nk})).ivk=Extract(SinsemillaCommitrivk(ak,nk)).

The Sinsemilla commit is one Sinsemilla hash (over the encoded ak,nk\mathsf{ak}, \mathsf{nk}ak,nk) plus a randomness term [rivk] Rivk[\mathsf{rivk}]\,R_{\mathsf{ivk}}[rivk]Rivk​. Cost: ~300 rows.

3.24 Flag-conditional logic​

Bundle flags determine whether spends and outputs are enabled per Action. If spends are disabled, the Merkle path check and nullifier publication are no-op'd (specific dummy values substituted). If outputs are disabled, the new note commitment and epk\mathsf{epk}epk are dummy.

In-circuit: each clause is multiplied by a flag bit, and a dummy-substitution gadget produces the public-input value when the flag is off. This is more complex than Sapling's "dummy when v=0v = 0v=0" because Orchard allows mixed-mode Actions (only spend, only output, or both).

3.27 Why each clause is necessary​

The "attack on omission" notes throughout this chapter all reduce to one of:

  • Money forgery: prove a non-existent commitment as spent; prove a value larger than the input.
  • Double-spend: produce different nullifiers for the same note.
  • Identity theft: spend a note whose recipient was not the prover.
  • Metadata leak: distinguish dummy from real spends.

Every clause in the circuits maps to one of these. If you cannot articulate which attack a clause prevents, the clause is suspect.

3.29 The verifier's view​

The Sapling Spend verifier checks one Groth16 pairing equation (chapter 04, section 3.7). Public inputs:

  • rk\mathsf{rk}rk (2 field elements).
  • cv\mathsf{cv}cv (2 field elements).
  • nf\mathsf{nf}nf (1 packed field element).
  • anchor\mathsf{anchor}anchor (1 field element).

The encoding is fixed and must match the circuit's expected order. If you change the public-input order, you must rerun the trusted setup.

For Orchard, the verifier runs Halo 2's verifier, ~10 ms vs ~7 ms for Groth16, with no trusted setup.

4. Failure modes​

See "Attack on omission" notes in each clause above and the consolidated list in section 3.27. Additional circuit-author mistakes from audit findings and informal lore:

  • Underconstrained advice cells: an advice cell with no gate forcing its value can be set arbitrarily by the prover. Verify every advice cell is used in at least one constraint with a selector on.

    Caught upstream by orchard::circuit synthesis tests (the MockProver from halo2_proofs exercises every cell). No automated test in this workspace; the Orchard circuit lives in the external orchard crate.

  • Off-by-one selector: a selector that is on at row iii but whose gate references row i−1i - 1i−1 can subtly misalign.

    No automated test in this workspace. Caught by audit only.

  • Incomplete-addition coincidence: as noted, both inputs must be provably distinct.

    Caught upstream by orchard::circuit::gadget::ecc unit tests in the external orchard crate. No automated test in this workspace.

  • Lookup-table collision: two distinct chunks mapping to the same point break the lookup soundness.

    Caught upstream by orchard::circuit::gadget::sinsemilla generator-table tests. No automated test in this workspace.

  • Public-input ordering: prover and verifier must agree on which public input maps to which constraint. A swap is invisible in tests until a real attack exploits it.

    Caught indirectly by: zcash_proofs::prover integration tests via parameter-hash verification (verify_hash against SAPLING_SPEND_HASH and SAPLING_OUTPUT_HASH in zcash_proofs/src/lib.rs). Any public-input reordering requires a circuit change, which would invalidate the pinned hashes.
